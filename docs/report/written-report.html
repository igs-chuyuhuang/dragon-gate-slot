五、關鍵開發軌跡紀錄

05/26 — 數學模型建立
🔧 數學模型 Agent：設計穿門倍率表（×15/×6/×3/×1），用 Python 模擬確認 RTP ~82%。發現純隨機穿門率過高導致 RTP > 100%，加入 MISS_BIAS 控制。
06/04 — 前端轉輪引擎完成
🔧 程式前端 Agent：實作 CSS transform 動畫引擎（fast→decel→overshoot→settle），支援 Turbo 模式。getCellH 用 Math.floor 解決不同解析度的 sub-pixel 問題。
06/15 — S23 Ultra 適配修正
🔧 程式前端 Agent：玩家回報 3088×1440 解析度 symbol 偏移。根因：reel 高度除 3 產生小數。修正：停輪後切換 flex 佈局自動等分。
06/17 — MG 輸贏邏輯重構
🔧 程式核心 Agent：原本「先扣全額+穿門補回」改為「穿門歸還本金+倍率獎勵」。WIN 只顯示純獎勵，本金靜默歸還。payoutCalculator 回傳 {winnings, refund, total}。
06/23 — 多人競賽系統上線
🔧 程式前端 Agent：實作姓名+組別輸入、倒計時、BIG WIN 暫停、Google Apps Script 排行榜、組別平均分排名。前後端 2 小時內完成。
06/25 — JP 機制從固定金額改為 Symbol Pool
🔧 數學模型+程式核心：原本用背景機率直接判定，改為三格獨立抽 pool（15 元素），依 bet 動態調整 JP symbol 比例。三同中獎，視覺上看到符號跟著轉。
06/25 — RTP 修正：普通門 ×3→×2
🔧 挑戰者 Agent 發現普通門×3 讓 RTP 超標。數學模型重算後調降為 ×2，配合 MISS_BIAS 20% 將 RTP 穩定在 ~82%。
06/29 — JP 視覺演出完成
🔧 特效爽感 Agent：全窄門紅金閃爍、JP 符號在中輪滾動時可見、停輪顯示結果、中獎飛移動畫到 badge 區。

美術素材生成的瓶頸與突破

開發初期使用 Pollinations.ai 批量生成素材，但遇到嚴重品質問題：生成風格不統一、解析度不穩定、構圖無法直接用於遊戲 UI。原始 AI 生成的畫面風格粗糙，與期望的國潮龍門主題差距甚大。

解決方案：改用 GPT 逐張生成單一素材圖片（撲克牌、龍珠、背景等），上傳到 GitHub 後透過 Agent 協助調整 CSS 座標與排版進行手工拼接。整個過程透過 Telegram 與 Agent 反覆描述位置座標，逐步微調到正確位置——等同於用自然語言「遙控」AI 做 UI 排版。

最終產出了風格統一的國潮龍門遊戲介面，所有元素（轉輪、按鈕、背景、吉祥物）視覺一致。

六、遊戲成果展示

遊戲畫面

核心玩法

3×3 盤面，每列獨立判定「射龍門」：左右欄決定門的上下限，中間欄開牌判定穿門。穿門倍率依門寬遞減（極窄×10、窄×5、普通×2、寬×1）。Scatter 收集滿 10 個可選擇 Free Game（8 轉免費+獎勵符號）或 Bonus Game（12 局牌局+保底）。全窄門時觸發 Jackpot 三格抽獎。

技術架構

game.html（主入口） ├── js/slotEngine.js ← 盤面產生 + MISS_BIAS ├── js/dragonGateJudge.js ← 穿門判定 + 倍率 ├── js/payoutCalculator.js ← 派彩（winnings + refund） ├── js/gameManager.js ← 狀態管理 ├── js/freeGame.js ← FG 邏輯 ├── js/bonusGame.js ← BG 邏輯（保底+all in） ├── js/effects/ ← 特效模組（winLine/wallHit/scatter） ├── css/game.css ← 全響應式樣式 └── Google Apps Script ← 排行榜後端 API

RTP 驗證（蒙地卡羅模擬）

10 萬次模擬顯示 RTP 穩定收斂至 ~82%。MISS_BIAS = 20% 是關鍵控制參數。

七、創新亮點總結

開發模式創新

10 Agent 協作開發：每個 Agent 有明確職責、持久記憶、獨立執行能力。Coordinator 負責拆解需求和品質把關，挑戰者 Agent 主動尋找 exploit 和平衡問題。這不是「用 AI 當工具」，而是「用 AI 組成團隊」。

完整閉環

市場調研→ 機制設計→ 數學模型→ 美術生成→ 程式開發→ QA 測試→ 部署上線

從概念到可遊玩的完整產品，全部由 AI agents 在 34 天內完成。涵蓋遊戲開發的每一個環節，沒有外包、沒有人工撰碼。

可規模化潛力

此開發模式可快速複製到其他遊戲類型：只需更換主題素材和數學模型，架構和流程完全可重用。同一套 Fleet 可以平行開發多款遊戲。
