# Scatter 累積收集制 機率分析報告

> 分析日期：2026-05-28  
> 模擬方法：Python 蒙地卡羅，每配置 200 萬轉  
> 模擬腳本：`math/scatter_collection_sim.py`

---

## 一、機制說明

| 項目 | 設定 |
|------|------|
| 盤面 | 3×3 = 9 格 |
| Scatter 出現率 | 每格 5%（可調） |
| 每轉期望 Scatter | 9 × 5% = 0.45 個 |
| 碰壁扣燈 | 每 row 15.4% 機率，觸發 -1 |
| 同值撞柱扣燈 | 每 row 0.59% 機率，觸發 -2 |
| 每轉期望扣燈 | 碰壁 0.46 + 撞柱 0.035 ≈ 0.50 |
| 淨期望增量 | +0.45 - 0.50 = **-0.05**（略為負值！） |
| 觸發條件 | 累積 ≥ 門檻 → 觸發 Bonus，歸零 |
| 燈號下限 | 0（不會變負數） |

> ⚠️ **關鍵發現**：淨期望增量為負值，代表系統依賴「運氣好的連續 Scatter 串」才能觸發，而非穩定累積。這使得觸發頻率遠高於理論值 `門檻 / 0.45`。

|------|----------------|--------|---------|

| 15 | 33.8 轉 | 540.0 轉 | **+1499%** |

> 碰壁扣燈機制對觸發頻率有**巨大影響**（門檻越高影響越大）。這是因為淨期望為負，系統本質上是「隨機遊走碰到吸收壁」的問題，而非簡單的線性累積。

## 五、建議方案

### 🏆 推薦：門檻 8 + Scatter Rate 5%

| 指標 | 數值 |
|------|------|
| 平均觸發轉數 | 123 轉 |
| 中位數 | 90 轉 |
| P25（幸運玩家） | 47 轉 |
| P75（一般玩家） | 164 轉 |
| 每 200 萬轉觸發次數 | 16,234 次 |

**選擇理由：**

1. **觸發頻率合理**：123 轉/次落在業界 80~150 區間中段
2. **體驗節奏好**：中位數 90 轉，多數玩家在 100 轉內能觸發，不會太挫折
3. **保持現有 Scatter Rate**：不需調整 5% 的設定，減少對其他系統的連鎖影響
4. **門檻 8 視覺友好**：UI 上 8 個燈號不會太多，進度感明確
5. **扣燈機制有效**：碰壁 -1 讓玩家有「差一點」的緊張感，增加刺激度

### 備選方案：門檻 10 + Scatter Rate 6%

如果希望門檻更高（視覺上更有成就感），可將 Scatter Rate 從 5% 提升到 6%，配合門檻 10，平均 91 轉觸發。但需注意：
- 提高 SR 會影響基礎 RTP 計算
- 門檻 10 的 P75 = 277 轉（部分玩家等待較久）

## 六、對 RTP 的影響評估

### 當前 RTP 結構（96.4%）
- 基礎派彩（穿門/碰壁）：佔大部分
- JP 系統：佔約 3-5%
- Scatter Bonus/Free Game：新增項目

### Scatter Bonus 的 RTP 佔比估算

假設 Bonus 獎勵 = 50× bet（業界常見）：
- 觸發頻率：1/123 轉
- Bonus RTP 貢獻 = 50 / 123 = **0.41%**

假設 Free Game 10 轉（平均獲利 30× bet）：
- FG RTP 貢獻 = 30 / 123 = **0.24%**

**建議調整：**
- 從基礎派彩中扣除 0.4%~0.7% 分配給 Scatter Bonus
- 或從 JP 貢獻中微調，維持總 RTP 96.4%
- 具體數值需配合完整 RTP 模擬確認

## 七、設計建議摘要

| 項目 | 建議值 | 說明 |
|------|--------|------|
| Scatter Rate | **5%**（維持不變） | 配合門檻 8 剛好落在目標區間 |
| 累積門檻 | **8** | 平均 123 轉觸發，體驗佳 |
| 碰壁扣燈 | **-1**（維持） | 增加緊張感，影響已計入 |
| 同值撞柱扣燈 | **-2**（維持） | 發生率低(0.59%)，影響可忽略 |
| 燈號下限 | **0** | 不會負數，避免挫折 |
| UI 燈號數 | 8 格 | 進度條/燈號視覺清晰 |

### 玩家體驗預期
- 🎯 50% 玩家在 90 轉內觸發（中位數）
- 🍀 25% 幸運玩家在 47 轉內觸發
- 😤 25% 玩家需要 164+ 轉（但不超過業界常見範圍）
